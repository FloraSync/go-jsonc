# go-jsonc v1.0.0

v1.0.0 is the first FloraSync release of `github.com/FloraSync/go-jsonc`.

This project is an independent continuation of Marco Zaccaro's

preserved.

## Breaking changes

- The module path is now `github.com/FloraSync/go-jsonc`.
- The package name is now `json`, matching `encoding/json`. Callers migrating
  from `github.com/marcozac/go-jsonc` may temporarily preserve the `jsonc`
  identifier with:
  `import jsonc "github.com/FloraSync/go-jsonc"`
- Go 1.26.0 or newer is required.
- Alternative JSON backend build tags and their third-party module
  dependencies have been removed.

## Features

- Provides a zero-dependency facade over Go's stable `encoding/json` API.
- Accepts line comments, block comments, and one trailing comma after the last
  member or element of a non-empty object or array.
- Adds length-preserving JSONC sanitization with original-input byte offsets.
- Provides JSONC-aware streaming decoding while retaining the documented
  `encoding/json.Decoder` operations.
- Keeps strict JSON on the standard-library fast path.

## Security and robustness

- Validates impossible byte counts returned by caller-supplied `io.Reader`
  implementations before slicing internal buffers.
- The condition was fixed before the first FloraSync release. No affected
  FloraSync release or conforming-input attack path was identified.
- See `docs/security/findings/FS-SEC-2026-001-invalid-reader-count.md` for the
  approved non-privileged engineering record.
